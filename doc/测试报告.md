## 六、代码安全审查

### 6.1 审查通过的模块

| 模块 | 文件 | 审查结论 |
|------|------|----------|
| Token 签发 | AuthTokenService | 安全。32 字节 SecureRandom 随机 token，Base64 编码 |
| 密码服务 | PasswordService | 安全。PBKDF2WithHmacSHA256，120000 次迭代，恒定时间比较，自动升级明文密码 |
| 用户上下文 | AuthContext | 安全。ThreadLocal 每次 afterCompletion 清理，无泄漏风险 |
| 密码保护 | User.java | 安全。@JsonIgnore 阻止 password getter 序列化 |
| 拦截器注册 | WebMvcConfig | 安全。/api/** 全拦截 + 白名单放行 /api/auth/login |

### 6.2 安全修复验证

本次修改解决的安全问题：

| 问题 | 修复方式 | 验证结果 |
|------|----------|----------|
| 无后端认证 | 新增 AuthInterceptor 拦截 /api/** | PASS（无 token 返回 401） |
| 密码明文返回 | User.password @JsonIgnore | PASS（登录响应无 password 字段） |
| 密码明文存储 | PBKDF2 哈希 + 明文自动升级 | PASS（MySQL 种子已用 PBKDF2） |
| 管理接口无后端保护 | AuthInterceptor 校验 admin 角色 | PASS（普通用户返回 403） |
| 审批人可伪造 | AuthContext.currentUserIdOr 优先取 token | PASS（SecurityIntegrationTest 验证） |
| 数据范围控制 | 各 Service.list() 按角色/部门过滤 | PASS（普通用户看不到 admin 创建的公文） |
| 印章保管人校验 | SealService 新增 requireKeeper | PASS |
| 前端主包过大 | ECharts 按需 + manualChunks | PASS（业务代码仅 75 kB） |
| SQL 种子不一致 | 补充 2000 人会议室 | PASS |
| 标准数据重复插入 | 唯一键 + ON DUPLICATE KEY UPDATE | PASS |

### 结论

本次修改成功实现了以下安全增强：

1. **认证鉴权**：基于随机 token 的后端认证拦截器，无 token 返回 401
2. **密码安全**：PBKDF2 加密存储 + API 响应隐藏密码 + 明文密码自动升级
3. **权限控制**：admin 接口后端校验 + 普通用户 403
4. **审批身份**：操作人从 token 获取，防止伪造
5. **数据范围**：公文/印章/会议/差旅/报告按角色和部门过滤
6. **印章权限**：用印登记和归还增加保管人角色校验
7. **前端优化**：ECharts 按需引入 + chunk 拆分，构建产物显著减小
8. **SQL 一致性**：种子数据与内存模式对齐，标准数据可重复初始化

系统核心功能稳定，所有自动化测试和手工测试均通过。建议后续关注 token 过期和登出机制。
