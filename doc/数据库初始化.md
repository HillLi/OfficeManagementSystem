# MySQL 初始化与持久化验证说明

项目采用前后端分离目录结构，后端在 `backend/`，前端在 `frontend/`。默认配置使用内存仓储进行快速开发和测试；启用 `mysql` profile 后，业务数据写入 MySQL 并在服务重启后回读。

## 1. 环境约定

| 项目 | 默认值 |
|------|--------|
| 数据库名称 | `office_management_system` |
| MySQL 客户端 | `D:\dev\mysql8\mysql-8.0.39-winx64\bin\mysql.exe` |
| Maven | `D:\dev\maven\apache-maven-3.9.14\bin\mvn.cmd` |
| 用户名 | `root` |
| 默认密码 | `123456` |

数据库连接配置位于 `backend/src/main/resources/application-mysql.properties`。本机密码不同时，应同步修改配置文件或使用适配的本地配置。

## 2. 初始化或升级数据库

在项目根目录执行：

```powershell
cd backend
powershell -ExecutionPolicy Bypass -File .\scripts\init-mysql.ps1 -Password '123456'
```

自定义客户端路径或账号时执行：

```powershell
cd backend
powershell -ExecutionPolicy Bypass -File .\scripts\init-mysql.ps1 `
  -MysqlBin 'D:\dev\mysql8\mysql-8.0.39-winx64\bin\mysql.exe' `
  -User root `
  -Password '123456'
```

脚本会顺序执行 `backend/sql/schema.sql` 与 `backend/sql/data.sql`。脚本可重复执行，并会为已有数据库补充当前业务闭环所需的结构，包括：

- `oa_document_distribution`：公文分发、签收与催办记录。
- `oa_seal_transfer`：印章移交记录。
- `oa_document`：版本与分发状态字段。
- `oa_meeting`：会议费用分项、大型活动材料及纪要字段。
- `oa_travel`：票据、超标准说明与报销状态字段。

## 3. 使用 MySQL 启动后端

```powershell
cd backend
& 'D:\dev\maven\apache-maven-3.9.14\bin\mvn.cmd' spring-boot:run -Dspring-boot.run.profiles=mysql
```

前端仍从独立目录启动：

```powershell
cd frontend
npm run dev
```

## 4. 持久化验收流程

建议在交付或修改持久化结构后按以下顺序验证：

1. 连续执行两次初始化脚本，确认新建数据库和已有数据库升级均无错误。
2. 以 `mysql` profile 启动后端，创建公文分发并签收、印章移交、会议费用和差旅报销数据。
3. 直接查询 `oa_document_distribution`、`oa_seal_transfer`、`oa_meeting` 与 `oa_travel`，确认字段已落库。
4. 停止并重新启动后端，通过接口再次读取上述记录，确认数据不是仅存于内存。

后端自动化测试命令：

```powershell
cd backend
& 'D:\dev\maven\apache-maven-3.9.14\bin\mvn.cmd' test
```
