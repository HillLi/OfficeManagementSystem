## 六、发现的问题

### P1 大型活动审批链与官网流程不完全一致

官网制度要求大型活动经保卫部风险评估后，还需报本单位主管校领导和学校主管保卫工作领导批准。当前 `ApprovalFlowConfig` 中 `meeting_large` 为：

`pending_security -> pending_dept -> approved`

该链路缺少明确的 `pending_leader` 或“学校主管保卫工作领导”审批节点。建议调整为：

`pending_security -> pending_dept -> pending_leader -> approved`

同时在流程导览、审批待办、通知角标中同步显示校级领导节点。

### P1 差旅标准仍是简化模型

官网《北京大学国内差旅费管理暂行办法》按人员类别、出差类型、交通工具、地区/城市、住宿标准、伙食补助、市内交通补助等维度约束。当前 `StandardTravelExpenseStrategy` 使用固定住宿基数、教学科研业务倍率、特殊地区伙食补助等简化算法，未完整落成制度标准表。

建议按 `oa_travel_standard` 建表/种子数据实现完整标准，并把交通等级、住宿上限、补助标准、超标说明全部走配置。

### P2 会议费缺少“国内管理会议特殊 600 元档”

官网会议费制度中，国内管理会议一般标准为 550 元/人天，参会人员包含 3 位及以上讲席教授及相当人员时为 600 元/人天。当前种子数据和内存标准只有：

- 国内管理会议：550
- 国内业务会议：950
- 在华举办的国际会议：1200

建议新增会议类别或字段标识特殊管理会议，并按 600 元档校验。

### P2 请示报告上级审批节点需按事项等级补齐

设计文档要求“请示/报告提交 -> 保密审查 -> 部门负责人审批 -> 上级审批 -> 批复 -> 归档”。当前通用流程为 `pending_secret_review -> pending_dept -> approved`，未按重大事项或跨部门事项显式触发校级/上级审批。

建议增加事项等级字段，并对重大事项、跨部门事项进入 `pending_leader`。

### P3 印章登记保留 10 年缺少显式保留策略

当前实现具备用印登记、材料、移交和审计记录，但未看到“登记簿保留 10 年”的显式生命周期策略或归档声明。建议增加数据保留策略说明，禁止物理删除或增加归档保留期配置。

## 八、验收建议

整改优先级：

1. 先修大型活动审批链，补齐校级/主管保卫领导审批节点，这是流程合规的关键问题。
2. 再补差旅标准表和会议费 600 元特殊档，避免费用规则与官网制度不一致。
3. 最后补请示报告事项等级和上级审批、印章 10 年保留策略说明。

整改完成后建议执行：

- 后端：`mvn clean test`
- 前端：`npm test`
- 前端构建：`npm run build`
- API 冒烟：登录、创建公文/用印/大型活动/差旅/请示报告并完整审批
- 浏览器冒烟：首页、审批中心、公文、印章、会议、差旅、请示报告标签页和待办角标
- MySQL 冒烟：使用 `mysql` profile 写入并重启回读关键业务数据
