# 高校办公管理系统（北京大学）设计方案

## 1. 项目概述

### 1.1 项目背景

基于北京大学（PKU）真实行政规章制度，设计并实现一套高校办公管理系统。系统覆盖公文管理、印章管理、会议管理、请示报告/保密管理、差旅审批等核心办公业务流程，集成AI智能审核和AI公文起草两项智能化功能。

### 2.2 架构风格

1. **MVC模式**：Controller处理HTTP请求，View由Vue前端承担，Model由Service+Entity承载
2. **三层架构**：Controller（展现层）→ Service（业务逻辑层）→ DAO（数据访问层），层间通过接口解耦

## 4. 业务模块设计

### 4.1 公文管理

**依据**：《北京大学规章制度管理办法》、《北京大学保密工作规定》

**业务流程**：
```
公文起草 → AI格式校验 → 部门审核 → 部门负责人审批 → 校办审核 → 校级领导签发 → 分发 → 归档
     │                                              │
     └── 退回修改 ←─────────────────────────────────┘
```

**功能清单**：
- 公文模板管理（通知、决定、请示、批复、报告、函等文种模板）
- 在线富文本编辑器起草公文
- AI智能审核公文格式（标题规范、文号格式、正文结构、附件检查）
- AI公文起草助手（根据主题和要点自动生成公文草稿）
- 多级审批流程（支持退回、催办、转办）
- 公文分发与签收
- 公文归档与全文检索
- 保密等级标识（公开/内部/机密/绝密）

### 4.2 印章管理

**依据**：《北京大学印章管理规定》校发〔2017〕41号

**业务流程**：
```
用印申请 → 用印材料上传 → 部门负责人审批 → 党办校办审核 → 用印登记 → 归还确认
     │                                    │
     └── 退回 ←───────────────────────────┘
```

**功能清单**：
- 印章台账（名称、类型、保管单位、状态）
- 用印在线申请（选择印章、上传材料、说明用途）
- 分级审批（校级印章需校领导批准，常规用印由部门负责人审批）
- 用印登记簿（日期、申请人、事由、审批人、经办人）
- 印章外带申请（须单位负责人批准）
- 印章移交记录
- 印章状态监控（在库/使用中/外带）

**关键规则（来自北大印章管理规定）**：
- 党办校办是印章综合管理部门
- 严禁在空白纸张上用印
- 各单位须建立用印登记簿，保留10年
- 印章遗失须立即向党办校办和保卫部报告

### 4.3 会议管理

**依据**：《北京大学大型活动安全管理规定》、《北京大学会议费管理暂行办法》

**业务流程**：
```
会议申请 → 会议室预定 → 部门负责人审批 → 会议通知 → 会议签到 → 纪要编写 → 纪要审批 → 归档
```

**功能清单**：
- 会议室资源管理（容量、设备、可用时段）
- 在线预定（冲突检测、自动推荐可用时段）
- 会议通知自动推送（邮件/站内消息）
- 会议签到（支持二维码签到）
- 纪要在线编写和审批
- 会议材料附件管理

### 4.4 请示报告与保密管理

**依据**：《北京大学保密工作规定》、《北京大学党务公开实施办法》

**业务流程**：
```
请示/报告提交 → 保密审查 → 部门负责人审批 → 上级审批 → 批复 → 归档
```

**功能清单**：
- 请示报告在线编写和提交
- 保密等级自动/手动标注（公开/内部/机密/绝密）
- 保密文件借阅审批流程
- 涉密文件访问日志记录
- 文件解密到期提醒

### 4.5 差旅审批

**依据**：《北京大学国内差旅费管理暂行办法》校发〔2019〕252号

**业务流程**：
```
差旅申请 → 行程填写 → 费用预算 → 部门负责人审批 → 财务审核 → 出差 → 报销申请 → 财务审批 → 归档
```

**功能清单**：
- 差旅申请（出发地/目的地/时间/事由）
- 自动计算差旅费标准（城市等级、交通工具等级、住宿标准）
- 多级审批流程
- 差旅报告提交
- 费用报销（发票上传、费用明细）

## 6. AI功能设计

### 6.1 AI公文智能审核

**功能目标**：在公文提交审批前，自动检查公文格式、内容是否符合规范，给出结构化的审核意见和修改建议。

**审核维度**：
- 标题格式：是否符合公文标题规范（如"关于XXX的通知"）
- 文号格式：是否正确（如"校发〔2026〕XX号"）
- 正文结构：是否完整（主送机关、正文、落款、日期）
- 保密等级：根据内容关键词建议合理的保密等级
- 制度引用：引用的制度文件是否存在于北大制度库

**技术实现**：
- 通过策略模式，不同公文类型使用不同的审核Prompt模板
- 调用大模型API（智谱GLM或OpenAI）进行审核
- 返回结构化JSON审核结果，前端渲染为可操作的审核报告

### 6.2 AI公文起草助手

**功能目标**：用户输入公文主题和要点，AI根据北大公文规范自动生成完整公文草稿，解决"不会写、反复退回"的痛点。

**技术流程**：
1. 用户选择文种，输入主题和要点
2. 后端构造Prompt，注入北大公文格式规范、对应文种模板结构、相关北大规章制度条款
3. 调用大模型API生成公文草稿
4. 后处理：格式规范化、自动生成文号、填入日期落款
5. 返回公文草稿，用户可编辑修改后提交审批

**支持的文种**：通知、决定、请示、批复、报告、函、公告

**两个AI功能形成闭环**：
```
[AI起草助手] 生成草稿 → 用户编辑 → [AI智能审核] 检查格式/规范 → 提交审批
```

## 7. 设计模式应用

### 7.1 创建型模式

**单例模式** — AI审核服务配置管理
- 全局唯一的AI服务配置（API Key、模型参数）
- Spring Bean天然单例实现

**工厂方法模式** — 公文对象创建
- `DocumentFactory.createDocument(type)` 根据公文类型创建不同的公文对象
- 每种文种对应一个具体工厂

**建造者模式** — 审批流构建
- `ApprovalChainBuilder` 逐步构建复杂的多级审批链
- 支持条件分支和并行节点配置

### 7.2 结构型模式

**代理模式** — 权限控制代理
- `SealServiceProxy` 在印章服务调用前检查用户权限、记录操作日志
- 通过Spring AOP实现

**装饰器模式** — 公文处理增强
- 基础公文处理 → 附加保密检查装饰 → 附加AI审核装饰
- 层层增强处理能力，不修改核心逻辑

**适配器模式** — 多AI服务适配
- `AIReviewAdapter` 统一适配不同大模型API（智谱GLM/OpenAI）
- 对外暴露统一接口，切换AI服务商无需修改业务代码

### 7.3 行为型模式

**责任链模式** — 多级审批流
- 审批请求依次经过：办公人员 → 部门负责人 → 校办 → 校领导
- 每人可批准/退回/转办

**策略模式** — 公文审核策略
- 不同公文类型使用不同审核策略
- 通知类简单审核 vs 合同类严格审核

**观察者模式** — 审批状态通知
- 公文状态变更时，自动通知申请人、下一审批人、抄送人
- 支持邮件和站内信两种通知渠道

**模板方法模式** — 业务处理流程
- `AbstractBusinessProcess` 定义通用流程：提交 → 审核 → 审批 → 归档
- 各业务模块子类实现具体的提交、审核、审批细节
