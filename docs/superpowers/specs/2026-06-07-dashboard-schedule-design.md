# 首页日程管理设计

## 背景

当前首页已经展示业务统计卡片、最新通知公告、公文状态分布、月度业务量和差旅预算概览。用户希望首页除了表单类统计数据之外，还能显示日历，并展示本月当前人员需要关注的会议、活动等日程。

本次设计将日程管理作为首页仪表盘的一部分扩展，不新增独立日程模块。日历只展示会议和大型活动，不展示待审批任务，避免审批待办和时间日程混在一起。

## 范围

本轮包含：

- 首页新增“日程管理”区域。
- 在首页显示本月日历。
- 在日历日期上标记当前人员本月可见的会议和大型活动。
- 展示本月当前人员的会议、活动列表。
- 点击日期后显示当天的会议、活动。
- 后端在仪表盘数据中返回本月日程数据，沿用现有会议权限口径。

本轮不包含：

- 在日历中显示待审批任务。
- 新增会议之外的通用日程创建能力。
- 新增提醒、重复日程、订阅或导出日历。
- 重做审批中心或会议管理页面。

## 方案选择

### 方案一：在 `/api/dashboard` 增加本月日程字段

推荐采用。首页原本就是仪表盘聚合页，将本月会议和大型活动放入 Dashboard 聚合结果，可以保持首页单次聚合读取。权限过滤在后端完成，前端只负责展示。

优点是权限口径集中、前端简单、和现有 Dashboard 结构一致。缺点是 Dashboard 响应会增加一个字段，但数据量只限定为本月，影响可控。

### 方案二：前端调用 `/api/meetings` 后本地筛选

实现最快，基本不需要后端新增 DTO。缺点是本月日程筛选、日历事件格式和首页业务逻辑都落在前端，后续扩展活动类型时容易变散。

### 方案三：新增独立 `/api/schedules/monthly` 接口

语义最清晰，也适合未来发展为独立日程中心。当前需求只服务首页，单独新增接口会让本轮改动偏重。

## 数据设计

在 `DashboardStats` 中新增：

- `monthlyScheduleItems: List<DashboardScheduleItem>`

新增 DTO 或模型 `DashboardScheduleItem`：

- `id: Long`
- `bizType: String`，本轮固定为 `meeting`
- `title: String`
- `startTime: LocalDateTime`
- `endTime: LocalDateTime`
- `status: String`
- `largeActivity: boolean`
- `roomName: String`
- `typeText: String`，前端可显示为“会议”或“大型活动”

数据来源为现有 `Meeting` 和 `MeetingRoom`。只返回当前自然月内与会议时间有交集的会议：

- `meeting.startTime < nextMonthStart`
- `meeting.endTime >= monthStart`

被拒绝的会议不展示。其余审批中、已通过、已归档会议都可展示，因为这些事项仍然体现当前人员的会议/活动安排或已发生记录。

## 权限口径

日程数据沿用现有 `MeetingService.meetings()` 的可见范围：

- 管理员、办公室管理员、校领导、保卫人员可见全部会议。
- 普通用户可见自己发起的会议。
- 部门负责人可见本部门人员发起的会议。

为了避免权限逻辑分叉，推荐在 `DashboardService` 中复用会议可见性判断，或抽出一个后端私有方法，让 Dashboard 聚合与会议列表保持一致。

## 首页交互设计

首页结构保留现有统计卡片、公告和图表。新增“日程管理”面板放在公告之后、图表之前。

面板分为两列：

- 左侧：本月日历。
- 右侧：当前选中日期的事项，以及本月事项列表摘要。

默认选中今天。如果今天不在当前显示月份，则选中本月第一天。日历只显示当前月，不做跨月翻页；本轮标题显示为“YYYY 年 M 月日程”。

日期格展示：

- 日期数字。
- 当天有普通会议时显示蓝色圆点。
- 当天有大型活动时显示橙色圆点。
- 今天有轻量边框强调。
- 选中日期有明确背景态。

右侧列表展示：

- 标题、开始结束时间、会议室、状态。
- 大型活动显示醒目的“大型活动”标签。
- 普通会议显示“会议”标签。
- 无事项时显示 Element Plus 空状态，文案为“当日暂无会议或活动”。
- 本月完全无事项时，日历仍显示，右侧显示“本月暂无会议或活动”。

## 前端设计

`Dashboard.vue` 增加：

- `monthlyScheduleItems` 响应式数据。
- 月份日期网格计算属性。
- 按日期分组的日程计算属性。
- 选中日期状态。
- 日程时间、日期 key、状态文本等格式化函数。

样式遵循现有首页 `panel` 风格，不新增重装饰卡片。日程面板在宽屏下使用两列布局，在窄屏下上下排列。

前端不新增第三方日历库。当前需求是只读月历，使用 Vue 计算属性渲染固定 7 列网格即可，能减少依赖和样式冲突。

## 后端设计

`DashboardFacade` 或 `DashboardService` 聚合本月日程：

1. 获取当前时间所在月份的起止边界。
2. 基于当前用户权限过滤会议。
3. 排除 `rejected` 状态会议。
4. 筛出与本月有交集的会议。
5. 按 `startTime` 升序返回 `DashboardScheduleItem`。
6. 补充会议室名称和日程类型文案。

`DashboardController` 保持现有 `/api/dashboard` 不变，只扩展响应字段。

## 错误处理和空状态

- 后端无会议时返回空数组，不返回 null。
- 前端使用空数组兜底，接口旧数据或异常字段不会导致首页渲染失败。
- 日期、时间为空时不渲染到日历，并在列表中以 `-` 兜底。
- 图表初始化逻辑保持不变，避免日程区域影响现有图表。

## 测试设计

前端测试：

- `Dashboard.spec.js` 检查页面包含日程管理区域、日历网格、日程空状态。
- 检查日历不渲染待审批任务字段或文案。
- 检查 Dashboard 响应中的 `monthlyScheduleItems` 被读取。

后端测试：

- `DashboardScopeTest` 或新增 Dashboard 测试覆盖当前用户只能看到权限范围内的会议日程。
- 覆盖只返回本月有时间交集的会议。
- 覆盖 rejected 会议不进入首页日程。
- 覆盖大型活动标记和会议室名称。

## 验收标准

- 首页在统计卡片和图表之外显示日程管理面板。
- 日历显示当前月，并标记本月会议和大型活动。
- 右侧能显示当前人员本月会议、活动，切换日期后只显示当天事项。
- 待审批任务不会出现在日历中。
- 现有首页统计、公告、图表不回退。
- 前后端相关测试通过。
