# 审批流程导览图设计

**日期**：2026-05-28
**项目**：高校办公管理系统
**范围**：所有需要审批的业务页面与审批中心，包括公文、用印、会议、请示报告、差旅。

## 1. 背景与目标

当前系统已经具备通用审批、待办任务、流程实例、审批记录、通知提醒以及各业务闭环能力，但这些信息分散在不同表格和弹窗中。用户提交申请后，只能看到当前状态，难以直观判断已经经过哪些节点、当前卡在哪个审批人或角色、后续还需要哪些办理环节。

本次新增“流程导览图”，目标是让发起人、审批人和有权限查看该业务的管理角色，在业务列表或审批中心就能看到完整流程路径、当前审批状态、历史审批意见和后续办理节点。

## 2. 方案选择

采用“通用流程导览接口 + 通用前端组件”的方案。

后端新增一个按 `bizType + bizId` 查询的流程导览接口，统一聚合应走路径、流程实例、待办任务、审批历史和业务闭环状态。前端新增 `FlowGuide` 通用组件，在公文、用印、会议、请示报告、差旅以及审批中心复用。

不采用前端自行拼装方案。流程规则如果散在多个页面里，后续状态展示容易不一致，也会让用印分级审批、会议大型活动、公文分发签收等分支维护困难。

不只增强审批中心。用户应能在业务发生的位置直接查看流程，不需要专门跳转到另一页才能知道申请状态。

## 3. 功能范围

### 3.1 覆盖业务

- 公文管理
- 用印管理
- 会议管理
- 请示报告
- 差旅审批
- 审批中心的待办任务和流程实例

### 3.2 展示粒度

流程节点展示以下信息：

| 字段 | 说明 |
|------|------|
| 节点名称 | 例如“部门负责人审批”“党办校办审核”“用印登记” |
| 节点类型 | `approval` 审批节点，`business` 业务办理节点，`system` 辅助或系统节点 |
| 节点状态 | `done`、`current`、`waiting`、`rejected`、`skipped`、`optional` |
| 处理角色 | 例如部门负责人、党办校办人员、财务人员 |
| 实际处理人 | 已处理节点展示实际操作人姓名 |
| 审批意见 | 已处理节点展示审批意见或业务办理说明 |
| 办理时间 | 已处理节点展示操作时间 |
| 截止时间 | 当前待办节点展示待办截止时间 |

权限沿用现有业务读取权限。用户能查看该业务，才能查看对应流程导览；无权限用户返回 `403`，不暴露审批意见或处理人。

## 4. 业务流程规则

流程导览展示的是“应走路径 + 当前进度 + 已办详情”。已经发生的节点展示处理结果，未发生但属于该业务路径的节点置灰等待。

### 4.1 公文

公文路径按设计文档中的公文规定展示：

```text
公文起草
  -> AI格式校验
  -> 提交审批
  -> 部门负责人审批
  -> 党办校办审核
  -> 校级领导签发
  -> 公文分发
  -> 接收人签收
  -> 公文归档
```

规则：

- “AI格式校验”为辅助节点。已调用 AI 审查则显示 `done`，未调用则显示 `optional`，不阻断提交审批。
- “部门审核”和“部门负责人审批”在当前实现中合并为“部门负责人审批”节点。
- “校级领导签发”对应当前 `pending_leader -> approved`。
- “公文分发”和“接收人签收”来自公文分发签收记录。
- “公文归档”是最终闭环节点。导览图只展示设计主线和当前状态，不新增“必须全部签收后才能归档”的业务限制。

### 4.2 用印

用印路径：

```text
保存草稿
  -> 上传材料
  -> 提交申请
  -> 分级审批
  -> 审批通过
  -> 用印登记
  -> 归还确认
```

分级审批按现有规则动态生成：

| 场景 | 审批路径 |
|------|----------|
| 部门常规用印 | 部门负责人审批 -> 审批通过 |
| 部门重大用印 | 部门负责人审批 -> 党办校办审核 -> 审批通过 |
| 校级常规用印 | 党办校办审核 -> 审批通过 |
| 校级重大用印 | 党办校办审核 -> 校级领导审批 -> 审批通过 |

“上传材料”根据有效附件数量判断。“用印登记”和“归还确认”根据用印申请状态、用印时间、归还时间和对应审批记录展示。

### 4.3 会议

普通会议路径：

```text
提交会议
  -> 部门负责人审批
  -> 审批通过
  -> 纪要归档
```

大型活动会议路径：

```text
提交会议
  -> 保卫部门审核
  -> 部门负责人审批
  -> 审批通过
  -> 纪要归档
```

是否大型活动沿用现有会议业务规则，不在流程导览中重新判定新阈值。

### 4.4 请示报告

请示报告路径：

```text
提交请示报告
  -> 保密审查
  -> 部门负责人审批
  -> 审批通过
  -> 批复归档
```

当前实现中“上级审批”未独立落为额外节点，因此导览图不凭空新增未实现节点。若后续流程配置新增校级或上级审批节点，通用导览接口可按配置扩展。

### 4.5 差旅

差旅路径：

```text
提交差旅
  -> 部门负责人审批
  -> 财务审核
  -> 审批通过
  -> 提交报销
  -> 财务复核
  -> 归档
```

“提交报销”来自差旅报销接口及报销附件记录。“财务复核”复用 `pending_finance` 节点；若报销复核通过后状态进入 `archived`，导览图展示为归档完成。

### 5.1 组装逻辑

后端服务按以下顺序组装：

1. 校验当前用户是否可读取对应业务。
2. 根据业务类型和业务实体生成应走路径。
3. 读取流程实例、待办任务、审批记录、业务状态、审计或业务闭环记录。
4. 合并每个节点的状态、处理人、意见、时间和截止时间。
5. 返回统一结构给前端。

### 5.2 数据来源

| 数据 | 来源 |
|------|------|
| 审批路径 | `ApprovalFlowConfig` 和业务实体属性 |
| 当前节点 | `FlowInstance.currentNodeKey` 与业务状态 |
| 当前待办 | `FlowTask` |
| 审批意见 | `ApprovalRecord` |
| 公文分发签收 | `DocumentDistribution` |
| 用印材料、用印、归还 | 附件、用印申请状态和审批记录 |
| 会议纪要 | 会议状态与纪要字段 |
| 请示批复 | 报告状态与批复字段 |
| 差旅报销 | 差旅报销字段、附件和状态 |

## 6. 前端设计

### 6.1 通用组件

新增 `FlowGuide` 组件，接收 `bizType` 和 `bizId`，打开时调用流程导览接口。

组件展示：

- 顶部摘要：业务类型、业务 ID、标题、当前状态。
- 主体：横向步骤条；窄屏下改为纵向步骤条。
- 节点详情：点击节点后展示处理角色、处理人、意见、时间、截止时间。
- 状态样式：完成节点打勾，当前节点高亮，退回节点红色，等待节点置灰。

### 6.2 页面入口

以下页面在业务表格操作列增加“流程导览”按钮：

- `Documents.vue`
- `Seals.vue`
- `Meetings.vue`
- `Reports.vue`
- `Travels.vue`
- `Approvals.vue`

审批中心中，待办任务和流程实例均可打开导览图。各业务页面中的入口用于申请人和管理人员就地查看；审批中心入口用于审批人处理前了解上下游状态。

## 7. 错误处理

- 无权限访问：返回 `403`，前端提示“无权查看该流程”。
- 业务不存在：返回业务不存在错误。
- 流程实例尚未创建：仍可基于业务状态展示草稿或待提交节点，后续节点置灰。
- 历史数据缺少部分记录：节点显示为 `waiting` 或 `skipped`，不让页面报错。
- 字典标签缺失：前端回退显示稳定编码，避免导览图空白。

## 8. 测试与验收

### 8.1 后端测试

新增流程导览集成测试，覆盖：

- 公文导览包含起草、AI格式校验、提交、部门负责人审批、党办校办审核、校级领导签发、分发、签收、归档。
- 用印导览按部门/校级、常规/重大生成不同审批路径。
- 退回后节点显示 `rejected`，重新提交后保留历史意见。
- 无权限用户访问导览接口返回 `403`。
- 差旅报销进入财务复核后，导览图能区分申请审批和报销复核。

### 8.2 前端测试

新增组件测试，覆盖：

- 完成、当前、等待、退回节点的状态 class。
- 点击节点展示处理人、意见和时间。
- `FlowGuide` 能在没有流程实例的草稿业务上展示基础节点。

## 9. 变更边界

本次只新增流程导览和状态可视化，不修改审批规则本身。

不新增 BPMN 流程编辑器。

不把公文分发、签收和归档顺序强制改成新的后端限制；导览图按设计文档展示主线，并忠实反映当前业务状态。

不对无权限用户暴露审批意见、处理人或业务闭环详情。
